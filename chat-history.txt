TOP 3 AREAS FOR IMPROVEMENT:

#1 — Urgency scoring is inverted (src/utils/urgencyScorer.js) — biggest impact.
   - "!" ADDS urgency (+30 each) -> thank-you notes spike to High.
   - Short messages SUBTRACT urgency (-40 / -60) -> terse emergencies sink to Low.
   - After-hours / weekend SUBTRACT -> 2am outage downranked. Backwards.
   - Zero urgency keywords; meaning ignored entirely.
   Worked examples (old code):
     "Database connection lost" -> 50-40 = 10 -> Low   (should be High)
     "Server down now"          -> 50-40-60 = -50 -> Low (should be High)
     "Thank you so much!...!"   -> 50+60-30 = 80 -> High/Med (should be Low)
   Why #1: Relay AI's value prop IS prioritize + route. Inverted urgency pushes
   the worst tickets to the bottom of the queue — worst possible failure.

#2 — Category classification brittle + nondeterministic (src/utils/llmHelper.js)
   - Prompt: "Categorize this customer support message: X". No taxonomy, no
     output format, no system role. temperature 0.7 -> nondeterministic.
   - Category chosen by substring-matching the model's prose
     (content.includes('billing')). "Not a billing issue" still tags Billing.

#3 — Wrong action templates + dead escalation (src/utils/templates.js)
   - Feature Request -> "Ask user to check billing portal." (copy-paste bug)
   - shouldEscalate() keys only off message.length > 100, ignores urgency and
     category, and is never called anywhere. Dead + wrong.
   - getRecommendedAction() takes urgency but never uses it.

Honorable mentions: silent mock fallback (fake result shown as real, no warning);
API key exposed in browser (dangerouslyAllowBrowser); no input validation;
unbounded localStorage history.

RECOMMENDATION: implement #1 (urgency scorer) — biggest difference, self-
contained, testable without an API key.

Offered options:
 (A) Scaffold urgencyScorer rewrite + test harness, leave keyword/weight logic
     as a marked TODO for the user to fill, then test together — recommended.
 (B) Implement it fully.
 (C) Tackle a different one.
